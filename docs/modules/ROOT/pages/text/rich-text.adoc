= Rich Text

include::../common.adoc[]

== Overview

Rich text is a sequence of text spans, where each span carries its own
text, font (family, size, weight and slant) and color. Unlike
xref:../layout.adoc[labels], which render a single style, rich text mixes
styles on one line, wraps lines across span boundaries, and shares a common
baseline between spans of different font sizes.

`rich_text` is a read-only element. The same span representation is also
used by `text_document` and `text_editor` for editable inline styles. Text
positions remain UTF-8 byte offsets in the concatenated text of a block, so
crossing a style boundary does not change caret navigation.

== text_style

`text_style` is the style used by editable runs:

[source,cpp]
----
struct text_style
{
   font_descr  font_;
   color       color_ = {};
};
----

An empty font family or a zero-alpha color inherits the block/theme default
when the style is rendered by `text_editor`. A `text_span` with an explicit
font and color remains absolute when passed directly to `rich_text`.

== text_span

The building block of rich text:

[source,cpp]
----
struct text_span
{
   std::string  text;
   font_descr   font_;
   color        color_;
};
----

`font_`:: The span font as a `font_descr`. Derive variants with the fluent
members, for example `.bold()`, `.italic()`, `.size(16)`.

`color_`:: The text color.

`text_span::style()` returns the corresponding `text_style`.

== rich_text

Creates a read-only rich text element:

[source,cpp]
----
rich_text(std::vector<text_span> spans, float width, int align)
----

`spans`:: The styled text, in display order.

`width`:: The wrapping constraint. Pass `full_extent` for a single,
unwrapped line.

`align`:: Follows the canvas text alignment semantics. Horizontal:
`canvas::left`, `canvas::center`, `canvas::right`; vertical:
top, middle, bottom (combine with `|`).

[source,cpp]
----
rich_text({
   text_span{"Mixed ", base, colors::black},
   text_span{"bold", base.bold(), blue},
   text_span{" text", base.italic(), red},
}, 200);
----

== Line wrapping rules

The wrapping engine is greedy and word based:

* Words are broken at whitespace boundaries. A word wider than the line is
  hard-broken character by character (UTF-8 aware). A single character wider
  than the line is placed anyway (the line may exceed the width).
* A hard newline ends the line immediately; consecutive newlines produce
  explicit empty lines, including a leading or trailing empty line.
  CRLF counts as a single newline. Spaces after a hard newline are
  preserved (they are significant in markdown, e.g. indented code blocks).
* Spaces pending at a wrap-induced line end are dropped; wrapped lines never
  start with a space.
* Spaces at the end of a span still join the next span's first word; each
  span contributes its own whitespace segment, measured in that span's font.
* The line height is the max of the span font heights; spans on a line
  share a common baseline equal to the line's max ascent.
* A truncated UTF-8 sequence at the end of a span is dropped (the malformed
  tail never reaches the backend). An invalid byte elsewhere is skipped
  and the decoder resynchronizes at the next byte.

== rich_text_layout

The layout engine behind the element, available for standalone use
(measurement, custom drawing):

[source,cpp]
----
rich_text_layout layout(std::vector<text_span> spans);
layout.layout(200);                    // wrap at 200 px
layout.draw(cnv, pos, canvas::left);   // draw at pos
auto s = layout.size();                // resulting extent
----

All measurement and drawing go through the canvas abstraction
(`measure_text` / `fill_text`); no backend-specific types are exposed.

== Editable rich text

`text_document` stores each block as an ordered `std::vector<text_span>`.
Adjacent runs with the same style are merged automatically. Plain string
constructors create inherited runs, so existing block-type font defaults
continue to work.

[source,cpp]
----
auto base = get_theme().text_box_font;
text_document doc({
   text_block{block_type::paragraph, std::vector<text_span>{
      {"normal ", base, colors::black},
      {"bold", base.bold(), colors::blue}
   }}
});

doc.insert({0, 11}, " text");       // inherits the bold run
doc.set_style({0, 0}, {0, 6},
   {base.italic(), colors::red});
----

Insertion, deletion, block splitting and joining preserve run styles.
`set_style` splits only the boundary runs and records the affected blocks in
the existing block-level undo history. `text_editor_element::apply_style`
applies the same operation to its current selection and repaints only the
affected region.

The editor lays out and caches blocks independently. An edit copies or
rebuilds only runs in the touched block; unrelated blocks keep their layout,
pixmap and string allocations.
